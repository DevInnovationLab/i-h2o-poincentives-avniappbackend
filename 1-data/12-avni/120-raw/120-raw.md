# 120-raw

Raw API snapshots, exactly as the Avni API returned them. **Append-only.**

```
pull_<YYYYMMDD>T<HHMMSS>Z.json
```

One file per pull. The stamp is UTC, so the directory sorts chronologically and
two pulls can never collide silently. A snapshot that already carries a stamp
keeps its name when it is published — re-stamping it would invent a second
identity for one pull.

## Why a pull can never be reproduced

The Avni API only ever shows **now**. There is no "as of" parameter, no
immutable version of a record, and no way to ask what a subject looked like
last Tuesday. Records are edited in place and voided in place; a pump renamed
or an encounter corrected after a pull is simply different on the next one.

That makes each snapshot **evidence**, not a cache. It is the only record of
what the source system said at that moment, and it is the only way to explain
why two runs of the same code produced different tables.

So: never overwrite a snapshot, never delete one to save space, never
"regenerate" one. Everything in `121-clean/` is derived from a snapshot by
code and can be rebuilt at will; nothing here can be rebuilt at all.

## How they get here

`Main.py tables --save-raw` writes a snapshot locally; `Main.py box` copies it
into the Box folder under its stamped name. Copies go via a `.part` file
inside the destination and are renamed into place, because Box syncs whatever
appears in the folder and a half-written snapshot would be published as-is.

## Box path

```
<AVNI_BOX_ROOT>/120-raw/
```

`AVNI_BOX_ROOT` defaults to the local Box Drive mount of the project's
`12-avni` folder; set it in `.env`.

## Privacy

A snapshot is the **entire dataset**, unredacted: real village names, operator
usernames, free-text grievances, photo URLs. It is never committed, never
attached to an issue, and never pasted anywhere. `*.json` is not on the
`.gitignore` allowlist and everything under `1-data/` is denied again on top
of that.
